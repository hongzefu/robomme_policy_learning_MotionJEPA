第一部分（给人看）

1 要做什么

在四任务 × 400 训练的两个 modulation 模型上——MotionMem（54.62%，v2-1600ep-m8x8-modul-motion-b128-80k@50000）与 Frozen Wan pooling（43.06%，v2-1600ep-m8x8-modul-wantp768-b128-50k@50000）——在新 benchmark b4e97f2 上测 RouteStick 与 VideoRepick：把示范里某一段的 motion token 换掉，看模型下一步是否跟着变。

只用同一局做供体（用户原话：「你先不要做跨局，你先用同一局来给我结论」）：布局、旋转角、颜色、路线等完全相同，只差被测的那一处。

2 RouteStick：第 j 步的四种干预

每一步有两个属性：去哪个按钮（左／右）、怎么绕中间柱子（顺／逆时针）；绕向错或碰错按钮当场失败。

干预供体（同一局，只改这一处）模型若在用这段 token，应看到
只翻绕向同一局的变体：第 j 步绕向反过来，其余全同第 j 步绕向跟着反，去的按钮不变
只翻左右同一局的变体：第 j 步去另一侧按钮，绕向不变（第 j 步起点在最边上的按钮时无另一侧，不做）第 j 步去另一侧按钮，绕向不变
两者都翻同一局的变体：左右、绕向都反两者都跟着变
置零第 j 段 token 全清零看去掉这段信息后是乱走还是照常

读数分两项，各自与不干预对比：「绕向是否跟供体」「按钮是否跟供体」；每个能走到的步 j 都测。

3 VideoRepick：第 k 次交换的两种干预

示范里三个同色方块被交换了 n 次，执行时第一次就要拿对目标块。

干预供体（同一局，只改这一处）模型若在用这段 token，应看到
换成同局另一次交换第 k 次交换那段 token 换成同一局第 k′ 次交换的 token（只适用于交换 ≥2 次的局）模型把第 k 次当成「第 k′ 次那两块在换」：第一次拿起改拿按此推算的目标位置
置零第 k 次交换段清零改拿「假如第 k 次没交换」时目标所在的块，或拿对率下降

新 benchmark 的交换搭档由距离现场决定、规格接口无法指定，所以不做「改搭档」的变体，改用同局另一次交换的 token。

4 为什么能保证只差一处（已实测）

  • 新 benchmark 的 episode_spec 能把 RouteStick 一局完全定死（旋转角、柱色、路线、每步绕向）；从自然局重建 spec 后，示范画面与原局逐帧完全一致（3 局实测：351/351、201/201、101/101 帧）。
  • 只翻第 j 步绕向或左右的变体，示范画面在第 j 段之前与原局逐帧相同，从第 j 段第一帧才开始不同。
  • 变体示范实际绕的方向与设定一致（3 局 13 段全部一致，翻转段也一致）。
  • easy／medium 本来不允许回头，生成「只翻左右」变体时只对供体局放开这条规则，被测的接收局不受影响。

5 跑完给出的结论

  • MotionMem 的 token 是否分别携带「绕向」与「左右」两种信息：各自的净跟随率与 95% 区间，按步 j 和难度给出。
  • Frozen Wan pooling 是否同样。
  • VideoRepick 交换段 token 是否决定第一次拿哪块。

1 已实测确认的 episode_spec 事实（本计划的前提）

1.1 RouteStick

项结论依据
spec 字段layout.rotation_deg、layout.obstacle_rgb（4×RGB）、objects.L、actions.nodes（L+1，取 0/2/4/6/8）、actions.node_slots（L+1，0..4）、actions.directions（L 个 clockwise/counterclockwise）RouteStick._load_scene 的 spec 分支
给 spec 后是否还随机旋转角、柱色、段数、路线、起点、绕向全部取自 spec，不再抽随机数同上；子代理核查 + 实测
能否从自然局重建 spec能：按 _load_scene 抽样顺序（theta → 4 柱色 → 段数 → 起点 → 每步邻居 → 每步绕向）复算实测 3 局（seed 3100003 hard、3100010 medium、3100011 easy）：自然局与重建 spec 局路线、绕向、按钮坐标 md5 全同，示范帧 351/351、201/201、101/101 逐位一致
只翻第 j 步绕向只改 directions[j-1]，路线不动，校验必过实测：示范帧从第 j 段第一帧才开始不同（j=2 → 第 51 帧；j=1 → 第 1 帧），之前逐位相同
只翻第 j 步左右第 j 步改去另一侧邻居；之后每步保持原相对方向（出界则反弹）；段数与绕向不变。easy/medium 原规则禁止非端点回头，用 sampling_config.parameters.configs[<难度>].backtrack=True 放开（只用于生成供体，接收局不受影响）。第 j 步起点在端点（0 或 8）时另一侧出界，跳过实测：hard（8→6→8…）、medium（4→2→4→6→8）均被接受，示范帧同样从第 j 段才不同；easy 端点起点那局按规则跳过
翻转后示范是否真按新绕向绕是。原样局 13 段（7+4+2）示范绕向全部 = spec；翻转第 j 步后，第 j 段示范绕向随之翻转、其余段不变实测：按 direction_fail 同一叉积公式对示范 eef 轨迹逐段算（脚本与输出归档于 records/spec-probe/）
必须显式传 difficulty不传时 __init__ 无条件改成 easy；段数超出难度范围抛 ValueError源码
示范结构第 j 个执行子目标在示范里对应第 50(j−1)+1 至 50j 帧（每段 50 帧）实测帧数 101/201/351 = 1+50L

1.2 VideoRepick

项结论依据
spec 能否指定交换搭档不能。搭档在每次交换开始时按最近邻现场解析；spec 里的 actions.swap_pairs[k].partner 只是预写期望值，与实际不符时 _verify_swap_binding 抛 SpecBindingError。发起者固定：第 1 次必为目标，后两位是其余两块的排列VideoRepick._load_scene、_verify_swap_binding（子代理核查）
因此「只改第 k 次搭档」的变体无法在布局完全不变的前提下生成；改发起者只对 k=2、3 可行且会连带改后续交换，不采用同上
本计划的同局做法不生成变体：把第 k 次交换段的 token 换成同一局示范里另一次交换（第 k′ 次）的 token。布局、颜色、旋转、目标完全相同，只是「第 k 次交换看起来像第 k′ 次那一对在换」不涉及 spec
第 k 次交换的帧区间[S+50(k−1), S+50k]，S 为进入交换阶段的步；与随机路径一致_refresh_swap_schedule

2 干预定义（全部同一局）

2.1 RouteStick：第 j 步

窗口：motion stride 16、window 33；W_j = 真实帧与第 j 段（示范第 50(j−1)+1…50j 帧）相交的全部窗口起点。供体 token 由「供体变体局的示范」在同样起点上编码得到，按起点精确替换（motion_swap_exact）。

组供体适用位置
S_swing同局变体：第 j 步绕向翻转全部 j
S_side同局变体：第 j 步去另一侧，绕向不变第 j 步起点不在端点
S_both同局变体：左右、绕向都翻同 S_side
ZW_j 置零全部 j

对照不单列组：重建 spec 的原样局示范与原局逐位一致（1.1），所以「换成原样重建局的 token」恒等于不干预；改用 NOOP_EQ 闸门证明替换通路本身不改动作。

⚠ 跨界窗口：W_j 首尾窗口会带到第 j−1 段末尾（与供体相同）和第 j+1 段开头（S_swing 相同；S_side/S_both 因后续路线改变而不同）。读数另按「只换完全落在第 j 段内的窗口」做一组 core 版（S_swing_core、S_side_core），两版都报。

2.2 VideoRepick：第 k 次交换

组供体适用
T_k←k′同局第 k′ 次交换段的 token（k′≠k，每个 k 取全部 k′）交换次数 n≥2
Z_kW_k 置零全部 k

预测物体：在交换表的位置模拟里把第 k 次交换的那对位置换成第 k′ 次那对位置，算出目标最终所在的方块 pred_k←k′；若 pred 与真实目标相同，该 (局, k, k′) 记为「无区分力」，只报不进主统计。Z_k 的对照物体为 swap_blind_k（假如第 k 次交换没发生，目标所在的方块）。

3 读数

  • RouteStick（第 j 步，干预后在第 j 步判定完成或失败时截断）：
    • swing_follow：第 j 步实际绕向（执行轨迹叉积符号，含当场失败的步）= 供体绕向；
    • button_follow：第 j 步首个触到的按钮 = 供体侧按钮；
    • own：仍按原步完成。
    • 基线：同一 (局, j) 的不干预运行碰巧与供体一致的比例。净值 = 干预 − 基线，按接收局 bootstrap 2000 次 95% 区间；分组 × j × 难度出表。
  • VideoRepick（首次拿起后截断）：拿 pred_k←k′ 的比例、仍拿对的比例、拿其他的比例；Z_k 读拿 swap_blind_k 与仍拿对的比例；基线为同局不干预。
  • 接收位置：只在不干预运行走到第 j 步起点（RouteStick）或第一次就拿对（VideoRepick）的局上做干预。
