3 两个任务的源码事实

3.1 RouteStick：一步对错由什么决定

源码 RouteStick.py 与 utils/route.py（b4e97f2）。一排 9 个按钮，可走节点是 0/2/4/6/8，奇数位 1/3/5/7 立柱。一局分两段：示范段拿杆、走 m 步绕杆、放回、回起点；执行段把同样 m 步再走一遍。每一步有两个互相独立的自由度：

自由度由什么决定约束
左右（去哪个按钮）generate_dynamic_walk 在 5 个节点上相邻随机游走；left = 编号增大端点 0 只能往左、8 只能往右。easy [2,3] 步、medium [4,5] 步不回头（首步后方向锁定，到端点才反弹）；hard [4,7] 步、xhard [8,10] 步可回头（每步约各半）
绕向（怎么绕过中间立柱）每步独立抛硬币 clockwise / counterclockwise，与左右无关clockwise = 从行进方向左侧绕过中间立柱

一步算对必须同时满足三条：到达正确按钮（水平 3 cm 内）、绕向正确（direction_fail 按轨迹叉积符号判）、途中没碰别的按钮。绕向错或碰错按钮当场整局失败。判定逻辑相对旧版未改，新版只加了 xhard 与注入接口。

⚠ 陷阱一：左右与绕向是两件事，供体段与接收段可以「只差左右」「只差绕向」「两者都差」，三种情形必须分开，否则看不出 token 改的是哪一个。⚠ 陷阱二：easy / medium 不回头，左右几乎被起点与首步锁死，「只左右不同」的供体主要来自 hard / xhard；起点在端点时翻转左右会走出盘外，这些位置不做。⚠ 陷阱三：绕向错当场失败，所以绕向必须直接从轨迹读，不能靠「这一步是否成功」反推。

背景（旧 orig16 模型的数，不是本次模型）：上次 RouteStick 的失败以绕向错为主，MotionMem 第 1 步 61 局失败中 39 局绕向错、22 局碰错按钮。

3.2 VideoRepick：第 k 次交换

3 块同色方块（easy / medium / xhard）。示范段拿起目标再放下，然后交换若干次：easy 1–2 次、medium 2–3 次、xhard 4–5 次；每次 50 步，两块对调位置，搭档为发起者的最近邻。执行段重复拿同一块 1–3 次再按按钮，第一次就拿错整局失败。首次拿起的判据绑定物体身份，在新版仍成立。

swap_blind_k 的定义：若第 k 次交换没发生、其余交换照常，目标应在的那一块；由交换表直接推出。

⚠ 陷阱：判据绑定的是物体身份而不是位置，所以 swap_blind_k 必须由交换表逐次推出，不能按「示范时的位置」直接取；第一次拿错即整局失败，读数只看首次拿起；hard 档不交换，不进局池。

4 上次怎么做的、这次改什么

上次（美东 11-10，aspen 2×A6000 + GreatLakes 8×A40，orig16 的 context 模型，stride 32）：RouteStick 按子目标位置 j，把与第 j 段示范相交的 motion token 窗口 W_j 换掉，三组为 Bsame（另一局同位置 j 的段）、Bcross（另一局其他位置的段，做一半位置）、Z（置零）；读第 j 步是否跟随供体（减去不干预时碰巧一致的基线，按接收局 bootstrap 2000 次取 95% 区间）与 i≠j 特异性矩阵。VideoRepick 只换第 k 次交换段的窗口 W_k，两组为 Bsame_k（同交换次数另一局的对应段）与 Z_k（置零），读首次拿起是仍拿对还是改拿 swap_blind_k。

上次的问题（代码核实）本次修法
sp_swap_prep::subgoal_differs 对 RouteStick 只要求供体「左右不同或绕向不同」随机抽，三种情形混在一组供体按「左右同否 × 绕向同否」分层，拆成对照、S_swing、S_side、S_both 四组（第 5.1 节）
sp_swap_readout::step_view 的跟随 =「到达供体侧按钮且绕向等于供体」联合判据拆成 button_follow 与 swing_follow 两项独立读数，各减各的基线
sp_swap_prep / fp_swap_prep 里 MOTION_STRIDE=32 写死stride 参数化，本次两个模型均为 16；W_j 的窗口数按 stride 16 重算并由 SWAP_SCOPE 把关
serve 与客户端只认旧模型种类policy_config 的 model_kind 映射、run_local 的 MODEL_KINDS / MOTION_KINDS、motion_client 认 wan_fixedpool768
干预运行跑完整局第 j 步判定完（成功或失败）即截断，省一半以上算力
子模块 856bc3a，无 xhard整合到 b4e97f2；局池用新 seed、难度显式传入，含 xhard

5 干预组定义与读数

5.1 RouteStick（每个能走到的 (局, j)；W_j 定义同上次，stride 改 16）

组供体段做哪些位置回答什么
A 对照另一局同位置 j，左右同、绕向同只做 j=1 与 j=2换成「内容等价」的 token 本身带来多少扰动噪声
S_swing另一局同位置 j，左右同、只绕向不同全部token 是否携带绕向
S_side另一局同位置 j，只左右不同、绕向同起点在端点使翻转出盘的位置不做token 是否携带左右
S_both另一局同位置 j，两者都不同全部两个因素同时被换时是否一起跟随
Bcross条件同 S_both，但取自其他位置 j′≠j一半位置时序位置绑定：别的位置的内容搬过来还管不管用
Z置零全部去掉该段信息后的行为

读数分开两项：button_follow（第 j 步到达供体侧的按钮）与 swing_follow（第 j 步实际绕向 = 供体绕向；绕向错当场失败也能从轨迹读出绕向）。另报 own 率（仍做原步）。i<j 的前序步仍与不干预比较，作特异性检查；第 j 步之后因截断不再读。

净跟随率(组, 读数) = P(干预后第 j 步与供体一致) − P(不干预时同一 (局, j, 供体) 上碰巧一致)
区间：按接收局 bootstrap，95% 区间
读数 ∈ { button_follow, swing_follow }，两项各算各的基线

怎么读：S_swing 上 swing_follow 净值显著大于 0 而 button_follow 不动，说明 token 携带绕向且可被单独改写；S_side 同理读左右；对照组两项净值应贴近 0，否则上面的效应要先扣掉扰动噪声。

5.2 VideoRepick（原口径不变，k 可到 5）

组供体读什么
Bsame_k同交换次数另一局的第 k 次交换段，换 W_k首次拿起：仍拿对 / 改拿 swap_blind_k / 其他
Z_kW_k 置零同上

读数是首次拿起落在三类中的比例，与同一批局不干预时的比例对比，按接收局 bootstrap 95% 区间。改拿 swap_blind_k 的比例显著上升，说明第 k 次交换的信息确实经这段 token 进入决策。
