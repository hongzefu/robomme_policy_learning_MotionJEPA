第一部分（给人看）

1 要做什么

在四任务 × 400 训练的两个 modulation 模型上——MotionMem（54.62%，v2-1600ep-m8x8-modul-motion-b128-80k@50000）与 Frozen Wan pooling（43.06%，v2-1600ep-m8x8-modul-wantp768-b128-50k@50000）——在新 benchmark b4e97f2 上测 RouteStick 与 VideoRepick：把示范里某一段的 motion token 换掉，看模型下一步是否跟着变。

只用同一局做供体（用户原话：「你先不要做跨局，你先用同一局来给我结论」）：布局、旋转角、颜色、此前的路线完全相同，只在被测的那一步开始不同。

模型范围：MotionMem 两个任务做全；Frozen Wan pooling 只做 RouteStick 前 3 步（不做窗口对照）和 VideoRepick。时间不够先砍 Frozen Wan（用户已同意：「可以，A 优先」）。

第一部分按用户点名由 Fable 起草、主会话核对（用户原话：「第一部分用 Fable 来写」）。

2 RouteStick：第 j 步的四种走法

每一步有两个属性：去哪个按钮（原方向／另一侧）、怎么绕柱子（顺／逆时针）；绕向错或碰错按钮当场失败。两个属性各翻一次，共四种走法：

原绕向反绕向
去原方向的按钮正确路径（原局，不干预）只翻绕向
去另一侧的按钮只翻左右两者都翻

用户原话：「这四种都要，就是它临近的这个往左往右 clockwise counterclockwise 都要测。就是和我们正确的路径相比，应该有其他三种情况。」

干预就是把第 j 段 token 换成其他三种走法的 token，另加一组置零：

干预供体（同一局的变体）模型若在用这段 token，应看到
只翻绕向第 j 步绕向反过来，其余全同第 j 步绕向跟着反，去的按钮不变
只翻左右第 j 步去另一侧按钮，绕向标签不变（起点在最边上的按钮时无另一侧，不做）第 j 步去另一侧按钮。不是严格只差一处，见表下说明
两者都翻第 j 步左右、绕向都反两者都跟着变。不是严格只差一处，见表下说明
置零第 j 段 token 全清零去掉这段信息后是乱走还是照常；兼作噪声对照

「只翻左右」「两者都翻」的限制：去另一侧按钮必然绕另一根柱子，弧在桌面上的实际一侧也随之改变，且该步之后的路线不同，所以这两组不是严格只差一处。对策两条：绕向同时按「相对行进方向的标签」与「弧在桌面哪一侧」两种口径读；另做一组只换完全落在第 j 段内窗口的对照。

读数分两项，各自与不干预对比：「绕向是否跟供体」「按钮是否跟供体」；每个能走到的步 j 都测。

3 VideoRepick：第 k 次交换的两种干预

示范里三个同色方块被交换了 n 次，执行时第一次就要拿对目标块。

干预供体（同一局）模型若在用这段 token，应看到
换成同局另一次交换第 k 次交换段的 token 换成同一局第 k′ 次交换的 token（只适用于交换 ≥2 次的局）模型把第 k 次当成「第 k′ 次那两块在换」：第一次改拿按此推算的目标位置
置零第 k 次交换段清零改拿「假如第 k 次没交换」时目标所在的块，或拿对率下降

新 benchmark 的交换搭档由距离现场决定、规格接口无法指定，所以不做「改搭档」的变体，改用同局另一次交换的 token。同样对照换 seed 的不干预翻转率（见第 5 节）。

4 同一局变体的已实测事实

  • 原局重建：新 benchmark 的 episode_spec 能把 RouteStick 一局定死（旋转角、柱色、路线、每步绕向）；从自然局重建 spec 后，示范画面与原局逐帧一致（3 局实测：351/351、201/201、101/101 帧）。
  • 「只翻绕向」变体：已实测 3 局，示范实际绕向与设定一致，第 j 段之前与原局逐帧相同。
  • 「只翻左右／两者都翻」变体：已实测能生成、第 j 段之前与原局逐帧相同；其实际绕向与段长尚未逐个核对，由开工后的闸门逐个核对。
  • xhard 每段 50 帧：尚未实测，由闸门核对。
  • easy／medium 本来不允许回头，生成「只翻左右」变体时只对供体局放开这条规则，被测的接收局不受影响。

5 怎么判断是真效应

每个被测步另跑 2 次换采样 seed 的不干预，加上置零组，作为噪声对照。只有「翻转组跟随供体的比例」显著高于置零组与换 seed 的翻转率，才算 token 携带该信息。主结论只按「第 1 步」与「第 2 步以后」两档合并给出，难度分层只作描述。

6 跑完给出的结论

  • MotionMem 的 token 是否分别携带「绕向」与「左右」两种信息：跟随率相对两种噪声对照的差值与 95% 区间。
  • Frozen Wan pooling 在 RouteStick 前 3 步与 VideoRepick 上是否同样（时间不够时此项缺）。
  • VideoRepick 交换段 token 是否决定第一次拿哪块。

3 读数（主分析与噪声对照）

  • 分母：不干预运行走到第 j 步起点的全部 (局, j)（VideoRepick：不干预第一次就拿对的局）。干预运行未走到第 j 步的记 unreached，按「非跟随」计入分母，并单列 unreached 率。
  • RouteStick 两个读数（干预运行在第 j 个执行子目标判定完成或失败时截断）：
    • swing_follow：第 j 步实际绕向 = 供体绕向。绕向按执行 TCP 轨迹相对「prev→实际首个触到的按钮」有向线的叉积符号（与 direction_fail 同式，含当场失败的步）；另出「物理弧侧」口径：相对原局 prev→原目标有向线的叉积符号。两种口径都报，S_side/S_both 以物理弧侧口径为主。
    • button_follow：第 j 步首个触到的偶数按钮 = 供体侧按钮。
    • 各组只对其被改的维度做主读数：S_swing 看 swing_follow、S_side 看 button_follow、S_both 两项都看；未被改的维度作为「是否被连带改变」的旁证。
  • 噪声对照（新增）：对每个接收 (局, j)（RouteStick）或接收局（VideoRepick）额外跑 2 次换采样 seed 的不干预，得「同输入不同采样」翻转率；Z 组给「纯扰动」翻转率。效应只在 S 组净跟随率显著高于 Z 组与换 seed 的翻转率时才算「token 携带该信息」。判定行 NOISE_BASE=PASS model=… pairs=<n> flip_rate=<x>。
  • 主分析口径：按 j=1 与 j≥2 两档合并总体，bootstrap（按接收局，2000 次）95% 区间；难度×j 分层只作描述。事先定义：区间下界 > max(Z 翻转率, 换 seed 翻转率) 记为「有效应」。每组报有效 n。
  • VideoRepick（首次拿起后截断）：T 组读拿 pred 比例；Z 组读拿 swap_blind_k 与仍拿对比例；都对照被选局换 seed 的翻转率（被选局按「第一次拿对」筛选，存在向均值回归，结果并列写明）。

7 规模与资源

  • 局池：RouteStick easy 8 / medium 16 / hard 16 / xhard 20 = 60 局；VideoRepick easy 10 / medium 20 / xhard 20 = 50 局；两模型共用。
  • A（MotionMem，优先）：RouteStick 不干预 60 + 换 seed 120 + 干预（7 组含 core，截断）约 1200；VideoRepick 不干预 50 + 换 seed 约 40 + 干预约 200。
  • B（Frozen Wan pooling）：RouteStick 只做 j≤3、组 S_swing/S_side/S_both/Z（不做 core）：不干预 60 + 换 seed 约 80 + 干预约 450；VideoRepick 同 A。
  • 合计约 2500 次运行（多数截断）；超出 5 倍才停。
  • 资源：GL 4 个单卡 A40 占位，每占位一个长作业步 srun --jobid=<hold> --overlap --exact --ntasks=1 --gpu_cmode=shared，内含两条通道（错开 45 s），每通道 = 1 模型服务 + 1 仿真客户端，XLA_PYTHON_CLIENT_MEM_FRACTION=0.40；aspen 2×A6000（他人已占 18.6/14.3 GiB）每卡 1 条通道，XLA_PYTHON_CLIENT_MEM_FRACTION=0.30，起跑前 nvidia-smi 复核余量。调度不区分硬件，空闲通道取下一分片。
  • 每卡 worker 数按实测显存定：冒烟时每个模型在 A40 与 A6000 上各起 1 个 worker，读 nvidia-smi 峰值显存 P（模型服务 + 仿真渲染 + A 的 encoder sidecar），每卡 worker 数 = floor((可用显存 − 2 GiB) / P)，上限 4；同时把 XLA_PYTHON_CLIENT_MEM_FRACTION 设为 P/卡显存 + 0.02，避免 XLA 预占吃满。CPU 按每 worker 2 核：占位规格相应提到 --cpus-per-task=8 --mem=96G（由本计划开工令放行）。判定行 WORKER_FIT=PASS model=… gpu=… peak_gib=… workers=…。11-10 一占位 3–4 个进程曾 OOM，原因是 XLA 默认预占，按上式设 fraction 后不再叠加。
