## 显存

四卡峰值 79429–79447 MiB / 81920 MiB。

**该数字不能直接当 OOM 余量判读**：`XLA_PYTHON_CLIENT_MEM_FRACTION=0.95` 使 JAX 启动即预分配约 95%
显存池，`memory.used` 反映池大小而非真实占用。OOM 判据是「300 步跑完未报
`RESOURCE_EXHAUSTED` / `EXIT_CODE=0`」，已通过。JAX 为静态编译、每步显存需求恒定，故 300 步不 OOM
可外推至 40k 步不 OOM。

## 供给侧对照（worker 是否为瓶颈）

- 需求：3.831 s/step × global batch 128 = **33.4 样本/s**
- 实测供给（`env-b-aws-replication.md` 六节 / `4task-motion-400ep/result.md`，均为与其他任务并行时测得，属下界）：
  400ep 库开启态 w4 **79.0** / w8 **80.4** 样本/s
- **供给对需求约 2.4× 余量**；本 run w8、96 vCPU 下仅占 8 核

结合上面的分层均值形态（慢步满载），判断 **worker 数不是当前瓶颈**，4.21% 的空隙更可能来自
XLA host 侧同步而非数据供给。未扫 w12 / w16 档（见下）。

## 40k step 外推

**40000 × 3.831 s = 153,260 s = 42.6 h = 1.77 天**（4 卡独占，GPU4–7 空闲）。

另需叠加：起始 XLA 编译约 10 min（本 run it1–it100 段含编译，均摊后前 100 步为 5.93 s/step）、
checkpoint 每 5000 步一次共 8 次（本 run 单次存盘约 4 s）。合计约 **43 h**。
