# X3：区间核实与区间内细分（ButtonUnmaskSwap，ep8 两模型 + 基线 ep4）

脚本 `scripts/interpret/analysis/x3_intervals.py`（只读 stage1 原始 npz 与客户端视频，不跑仿真、不用 GPU）；分流复用 `scripts/interpret/aggregate_attn.py::split_streams`（全层、全头平均；去噪步／动作 query 拆分时只在对应轴上取单个下标）。全部数字在 `x3_summary.json`。

判定行：`X3_INTERVALS=PASS vis=[0,32) swap1=[64,114) swap2=[114,164) figs=6`

## 一句话结论
视频核实的区间与源码推得的完全一致（裸露窗 [0,32)、ep8 两次交换 [64,114)／[114,164)；基线 ep4 只交换 1 次 [64,114)）。修正 motion 窗的计权后，motion 模型在 #15～#19 的「motion 流落在交换区间」占比从旧口径的 57～92% 降到 22～48%，**#15、#17、#18 都低于修正口径的均匀期望**；旧口径的「靠近阶段盯交换」主要来自起点 160 的那个窗（[160,193)，只有 4 帧落在第 2 次交换里）被整窗计入。帧流方面 motion 模型对裸露窗的偏好（#16～#19 占 15～21%，均匀 12.5%）稳定存在，基线两局都低于均匀（3.6～14%）。

## 1. 区间核实（证据：fig_x3_1、fig_x3_2）
- **视频帧号＝全域帧号**：客户端视频 = reset 观测 1 帧 + 每执行 1 个动作 1 帧（`examples/robomme/eval.py::eval_each_episode` 的 `record_frame`）；帧上「Frame: i」文字与帧号一致。ep8 基线视频 311 帧、`actions_executed=310`；motion 313 帧；ep4 318 帧。npz 的 `step_idx`／`frame_times` 就是这个坐标（推理 #k 的 `step_idx = 16k`）。
- **裸露窗**：base 视角绿色方块像素数在帧 0～31 恒为 156（ep4 为 140），帧 32 变 0；容器掩码在 31→32 跳变 824 像素（ep4 1039）。即容器在 reset 时已被移开（帧 0 方块就可见，没有可见的「抬起」过程），帧 32 一次性落回盖住（瞬移，无下落过程）。**VIS = [0,32)**，与源码 `lift_and_drop_objects_back_to_original(start 0, end 64)` 的中点 32 一致。
- **交换**：容器掩码逐帧变化在帧 64 起跳（63→64：基线 166、motion 150、ep4 139 像素，之前 <10），帧 164 是最后一帧有变化（基线 178、motion 166），帧 165 起 <40（静止）。段内变化量中位数约 250，在帧 114（基线 36）／115（motion 61）有一处谷底，是两段 smoothstep 交接处速度为 0 的位置。等长切分点 114 与谷底相差 ≤1 帧，取 **SWAP1 = [64,114)、SWAP2 = [114,164)**（在途帧写法，帧 164 为到达终点位姿的那一帧）。与源码 `swap_schedule` 完全一致，因此「核实后边界」与「名义边界」下的所有数字相同（`nominal_equals_verified_ep8=true`），不另列两套。
- **基线 ep4（seed 570400）只交换 1 次**：移动段只有 [64,114)，帧 115 起静止，无谷底。所以 ep4 的交换区间是 [64,114)，不是 ep8 的两段。
- 附带：ep8 两局在帧 ≈302 起绿色像素重新出现（容器被抬起、露出方块），ep4 全程没有重新出现（失败局）。

## 4. 去噪步与动作 query（fig_x3_6，#15～#19）
去噪步 0＝从纯噪声开始的第一步（`attn_adapter.py` 的 while_loop 计数顺序）；动作 query 0＝块内第一个（最近执行的）动作。
- **去噪步**：motion 模型帧流 VIS 占比在去噪早期更高、后期回落：#18 前 3 步均值 19.8% → 后 3 步 13.0%，#19 18.9% → 11.2%，#16 21.7% → 18.3%；基线两局各步几乎持平（ep8 #18 3.9% → 3.9%）。motion 流 SWAP（修正）在 #16 早期 55.5% → 后期 35.7%，其余推理各步持平（#18 31.5 → 30.6）。即 motion 模型的「回看」主要在去噪前半段。
- **动作 query**：motion 模型 VIS 占比在近期／远期 query 间差别不大（#18 q0～4 15.1% vs q15～19 15.6%）；#16 远期动作更看 VIS（26.4% vs 15.7%）与 SWAP（q5～19 约 50% vs q0～4 21%）。基线 ep8 #15/#16 远期 query 的 VIS 占比更高（17.6 vs 12.9、13.8 vs 7.6），#17 反过来（3.5 vs 10.5）；没有一致趋势。

## 关键发现
1. 区间核实通过：VIS=[0,32)、SWAP1=[64,114)、SWAP2=[114,164)，视频帧号＝全域帧号；容器在 reset 时就不在原位，帧 32 瞬间落回，没有「抬起」过程；**ep4 只交换 1 次**（[64,114)），之前若按 k=2 处理 ep4 需更正。
2. 旧口径把 motion 流交换占比高估 2～4 倍：#15 92.2% → 21.7%、#18 61.0% → 30.5%；修正后 #15、#17、#18 低于均匀期望，「靠近阶段盯交换」的结论不成立，只剩 #16 对第 2 次交换的偏好（44.1% vs 19.7%）。
3. motion 模型对裸露窗的帧流偏好是稳定的：#16～#19 15.5～21.0%（均匀 12.5%），VIS 内 4 帧大致均匀分配；基线 ep8 在 #17～#19 只有 3.6～4.4%，失败局 ep4 4.1～10.0%。
4. motion 模型的 VIS 回看集中在去噪前半段（#18 19.8% → 13.0%），基线无此趋势。
5. 量级提醒：上述都是帧流（总质量 1.0～1.9%）与 motion 流（0.26～0.90%）内部的比例，注意力主体仍在当前图像、文本与动作 token。

## 局限
- 单局（ep8）+ 一局失败对照，单 seed；attention 不是因果。
- 区间由 base 视角像素阈值（绿色 HSV、容器低饱和高亮）量出，阈值手设；SWAP 分界取等长切分点 114，谷底在 114／115，有 ±1 帧不确定（对 32 帧稀疏采样的归属无影响：114、115 都不是 #15～#19 的记忆帧）。
- motion 窗按 [t,t+33) 均匀计权是近似：窗内 token 实际对哪几帧敏感未知。
- 去噪步／query 拆分在单次推理上做，格内数字波动较大（fig_x3_6 各格单独着色，跨列不可比色）。
