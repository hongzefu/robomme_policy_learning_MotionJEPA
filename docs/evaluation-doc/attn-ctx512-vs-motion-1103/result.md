# attn-ctx512-vs-motion-1103 第一阶段结果

## 一句话结论
ButtonUnmaskSwap 第 8 局（easy，seed 570800，交换 2 次）两模型都成功；在「揭开」那次推理（第 18 次，step 288，发出 step 288～303 的动作，视频第 288～304 帧容器被抬起、第 304 帧露出绿色方块）上，ctx512+motion 在帧流里落在裸露窗口 [0,32) 的占比 17.0%（均匀期望 12.5%），基线只有 3.6%；motion 流落在交换区间 [64,164) 的占比 30.5%（均匀期望 35.0%，重叠/33 口径，首版沾边口径为 61.0%／55.6%，见下方更正）。但两模型帧流总质量都很小（基线 0.90%、motion 1.35%，motion 流 0.26%），注意力主体在腕部图像、文本与动作 token 上；这是单局单次推理的「看哪里」观察，不是因果结论。


> **口径更正（2026-11-03，X3）**：本节及下方「前后 5 次推理」表中 motion 流交换区间占比用的是旧口径「窗口与区间沾边即整窗计入」，偏高。按「重叠帧数/33」计权后：#15 92.2%→21.7%（均匀 45.0%）、#16 85.5%→（SWAP2 44.1%，均匀 19.7%，唯一明显高于均匀）、#17 69.2%→22.1%（39.4%）、#18 61.0%→30.5%（35.0%）、#19 57.5%→36%；即抬起前后 motion 流对交换区间并无偏好。帧流口径不受影响。详见 analysis/x3/README.md。

## 可解释性深挖（X1–X4，围绕裸露窗与交换区间）
用户原话：「就对于这个任务 更加详细的挖掘可解释性 用多个subagent来 不同worktree 全部opus」「我关注的还是这几个区间」。四个 opus 子代理各在独立 worktree 只读已存 npz 与视频，逐个审查、目视复查后 --no-ff 合入。明细见 analysis/x1～x4/README.md。

**区间核实（X3）**：视频帧号 = 全域帧号（reset 1 帧 + 每动作 1 帧）。裸露窗 [0,32)：reset 起三色方块就露在外面，第 32 帧容器瞬间落回盖住（视频里看不到抬起过程）；交换 [64,114)、[114,164) 与源码一致，第 165 帧起静止；基线 ep4 只交换 1 次 [64,114)；ep8 约第 302 帧抬起后绿方块重新出现。

**基线 ctx512（不会回看裸露窗）**
- 整局自 #4 起帧流裸露窗占比约为均匀的 0.3～0.9 倍、始终 <1，成功局 ep8 与失败局 ep4 一样（X2）；去 sink 后仍低于均匀（X4）。
- 注意力几乎只看最近几帧：最大记忆头 L15H1 质量 0.759，99.8% 落在最近 4 帧（X1）；基线 #18 帧流 63～64% 在当前帧 t=288（X4）。
- 交换期间（#4～#13）偏向「交换 1」那批帧，主要是近因——那时它们就是最新的帧（X2/X3）。
- 失败 ep4 与成功 ep8 的差别出现在张开靠近 #14～#17：ep8 仍让交换 1 高于均匀（r=1.24），ep4 降到 0.77；抬起 #17～#19 差别消失（X2，单对观察）。两局头结构几乎相同（r=0.996，top-10 10/10，X1）。

**ctx512+motion（帧流稳定偏向裸露窗，motion 流不盯交换）**
- 帧流裸露窗：动作 query 整局多数推理高于均匀，#16～#19 为 15.5～21.0%（均匀 12.5%），窗内 4 帧大致均分（X3）；去 sink 后不变（17.2%，均匀 13.1%，1.3 倍，X4），这是四个方向里最稳的一条正向信号。帧流总质量约为基线 3 倍。
- 由少数头承担：L16H0（帧流质量 0.464、VIS 富集 1.81，但逐次波动大）与 L3H0（0.110、3.65 倍）合计约 69% 的正 VIS 超额；与基线回看 VIS 的头几乎不重合（X1）。
- 回看偏去噪前半段：#18 前 3 步 19.8%、后 3 步 13.0%（X3）。
- motion 流对交换区间：按重叠/33 计权后几乎都低于均匀，第 1 次交换基本不看（2.5～9.4%，均匀 17.5～22.5%）；只有张开靠近的 #16 对第 2 次交换明显偏高（44.1%，均匀 19.7%）（X3）；无稳定的 SWAP 专门头（X1）。
- 文本「green」query 的裸露窗偏高主要是 sink：t=0 帧占帧流 25.9～39.8%、其中单 token 占 73.4～98.8%，去 sink 后 37.8%→20.8%，#15/#18/#19 回到均匀附近（X4）。

**画面位置与文字（X4）**：文本 query 看记忆只占 5.4～8.0%，8 个词之间看不出分工；动作 query 在被看的历史帧里 4×4 近乎均匀（最大块 1.07～1.6 倍），没有对准绿方块或容器；当前图像里 wrist 视角占 prefix 36～48%，集中在被抓容器边缘与指尖。

**总体读法**：两个模型的注意力主体都在当前图像（尤其 wrist）、文本与动作 token 上，记忆区只占约 1～3%。在这一小块里，motion 模型稳定地多看开局方块裸露的那几帧，基线则几乎只看最近帧；两者都没有表现出「在抬起时回看交换过程」的模式，motion 流对交换的偏好只在靠近阶段的 #16 出现过一次。

**局限**：基线 2 局（含 1 局失败）、motion 1 局，单 seed；attention 只说明「看哪里」，不是因果；均值掩盖步间与头间差异，Gemma 多 query 头共享 KV；sink 只做了「剔除每帧最大 token」的粗对照；motion 窗按 [t,t+33) 均匀计权是近似。

## 全量 prefix attention 再分析（R1–R4）
用户原话：「可以重新运行一遍……现在可以获得所有的这个呃注意力的信息，就是包括 prefix 里面所有的attn 然后做一次更好的分析」「使用多个 agent 进行可解释性。」「同意开始」。

**数据**：S6 给采集链加 `--save-prefix`（默认关；GPU 自检两模型 `prefix_rowsum_err` 3.5e-7／3.6e-7、`prefix_same_actions=1`），本机重跑基线 ep4／ep8 与 motion ep8，三局 60 次推理的动作与动作 attention 和第一轮逐位一致（`REPRO_CHECK actions_bitexact=1 max_action_diff=0`），另存每次推理 prefill 各层 prefix 全量 attention（18×8×P×P，共 26 GB，在本机 v1-store/evaluation/interpret-1103/stage1b/，不进 git）。四个 opus 子代理各在独立 worktree 分析，均经合并前审查（R1 两轮）、目视复查后合入；明细见 analysis/r1～r4/README.md。

**先要知道的结构**（R1/R2/R3 实测）：prefill 时记忆区是封闭块——记忆 query 只看记忆区，当前图像 query 看不到记忆区（质量均为 0）；文本看记忆（第 0/1 层很重：基线 72%/17%、motion 60%/56%）；动作看全部，但只有约 1～3% 给记忆区。全局只有一个 sink：文本 `<bos>`，动作 query 约 23～26% 的注意力给它。

**问题 1：基线「只看最近帧」是否借记忆区间接读到了裸露窗？——按 attention 看不出来**
- R1 rollout：#15～#19 基线帧流 VIS 直接 7.0%／6.7% → rollout 1.7%／1.8%（均匀 13.1%）；只走记忆子块也只有 6.0%。在该近似下看不到间接读取（rollout 过平滑、忽略 MLP/残差，不能排除其他通路）。
- R4 逐层：基线一跳间接（经中转 token 读 VIS）格级中位数 0.17×（ep8）、0.20×（ep4），41%／38% 的格低于 1/8×；最大的一股是 L15 经最近帧的 0.0041，富集也只有 0.33×。
- R2 记忆区内部：头平均时最近帧→VIS 0.24×；但个别头很强——L14H6 让最近帧约 88% 的注意力落在 VIS 4 帧上（#18 富集 7.04×），L1H0 类似。这条头级通路在头平均与 rollout 里被稀释，是否真被动作用到需消融才能判断。

**问题 2：motion 模型对裸露窗的偏好是否稳健？——是**
- R3 去 sink 后帧流 VIS 17.2%→16.8%（均匀 13.1%，1.28 倍），压力测试再剔 6 个 motion 窗仍 16.5%。
- R4：直接读取集中在 L3（富集 2.31～3.11×）与 L16（1.71×），与 X1 的 L3H0／L16H0 一致；送到动作的 VIS 量（直接+间接）约为基线 5～8 倍。
- R1：只走记忆子块时 motion 模型 VIS 21.0%（1.6 倍）。

**问题 3：motion 流是否在读交换过程？——没有稳定证据**
- R3：motion 流 SWAP1 去 sink 后仍低于均匀；唯一高于均匀的 #16 SWAP2 偏好，落在一个被记忆区 query 当作 sink 的窗 [128,161) 上，压力测试下翻转。
- R2：motion token 在记忆区内部是强汇聚点（帧 query 约 58% 给 9 个 motion token），但汇聚的主要是 [224,257)、[160,193) 等非交换窗；覆盖交换期的 motion 窗读交换期帧只有 0.40×。

**问题 4：失败局 ep4 与成功局 ep8 有何不同？——attention 层面几乎看不出**
R2/R4 逐层逐头几乎重合（L14H6 #18 富集 7.02× vs 7.04×；L15/L16 间接 ep4 反而略高）。X2 看到的「张开靠近阶段 SWAP1 偏好差别」在逐层通路里没有对应的结构差异。

**总体读法（更新）**：两模型在动作端读记忆的量都很小；motion 模型稳定、且去 sink 后仍成立地多读开局方块裸露的那几帧，主要由 L3、L16 少数头直接承担；基线在头平均与 rollout 口径下都不回看裸露窗，但记忆区内部存在把最近帧连到裸露窗的单头通路（L14H6），其作用尚未验证。两模型都没有表现出读交换过程的稳定模式。要回答「靠什么完成任务」，下一步需要因果实验（遮掉 L14H6、L3/L16 头或 motion 窗后看动作与成功率变化），本轮未做。

**局限**：基线 2 局（含 1 失败）、motion 1 局，单 seed；只存了注意力概率、没有值向量，无法按 ‖v‖ 加权；rollout 与一跳间接都是 attention-only 线性近似；sink 阈值手设（已给敏感性）。

## 因果实验：遮挡与 motion 内容替换（12 局）
用户原话：「注意力只能说明模型「看了哪里」，不能证明它「靠这个做决定」……做一下 不用我再批准了 直接开始」「你不应该是把 motion 全部去掉，你应该是把 motion 替换为这个平凡的变量，或者替换为临近的任务的 motion。」

**设置**：10-31 官方评估中 motion 模型在 ButtonUnmaskSwap 成功的 12 局（4/8/11/12/17/18/20/26/34/37/38/40，seed 42），本机 2×A6000，两模型同一批局。代码：S7 遮挡开关（key 遮挡只改 attention mask 的 key 列、位置不动；头遮挡把该头输出置零，GPU 自检 `ablate_off_same=1 masked_cols_mass=0 head_zero_ok=1`）、S8 motion 内容替换（只换编码内容，token 数/位置/mask 不动；带记录重跑正常组与原正常组 12 局结局相同、279 次推理动作最大差 0）。motion_swap 每局换成列表中下一局同起点窗口的编码，12 局全部窗口都被替换，动作自第 2 次推理起偏离。

**读法**
- 基线：遮挡后成功局与失败局大面积互换，总数在 4～6 间波动——基线在这批局上选容器接近随机，对它谈不上「依赖什么」。
- motion 模型离不开「像样的」motion 输入：换成全 0 或整体遮掉，几乎全部失败（1/12、0/12，平均每局 77～82 次推理即跑满步数仍未完成）。
- 但它不太依赖「本局」motion 里的具体内容：换成相邻局的真实 motion，仍有 8/12 成功，只比正常少 3 局（失去 17/20/34/40，多出 26）。若模型主要靠本局 motion 记住交换去向，换成别局交换过程的 motion 应大幅降到接近随机，实际没有。
- 遮掉开局裸露窗那几帧（9/12）或注意力分析找到的两个头 L3H0、L16H0（8/12），也只少 2～3 局。
- 合起来：motion 模型对 motion 流的依赖更像「需要分布内的 motion 信号才能正常工作」，而不是「靠本局 motion 内容追踪交换」；本局内容、裸露窗帧、L3/L16 头各自贡献一些，但单独去掉都不致命。

**结论修正（写完整报告时补算，见 [report.html](report.html)）**：上面「不太依赖本局内容」说重了，改为「尚无结论」。配对符号检验（只看翻转局，精确双侧）：swap −4/+1 p=0.375，zero −10/+0 p=0.002，全遮 −11/+0 p=0.001，遮裸露窗 −3/+1 p=0.625，遮两头 −3/+0 p=0.25；基线遮裸露窗 −2/+4 p=0.688，遮 L14H6 −3/+4 p=1。事后拆分：供体与本局交换次数相同的 3 局（12、18、26）swap 下全部成功，不同的 9 局成功 5 局（单侧 p≈0.25，只作线索）。12 局是 10-31 seed 42 该任务 50 局里 motion 模型成功的全部局，所以 swap 8/12 与全部 50 局的 24% 不可直接比较。

**局限**：每组 12 局、单 seed，±2～3 局的差别在这个样本量下不显著（逐局翻转也可能来自动作扰动）；swap 的供体与本局交换次数/方向可能部分相同，没有控制；全 0 也属分布外，只能说明「需要合法 motion 信号」；只做了这一任务。要把「本局内容」的作用量化清楚，需要更多局和交换方向明确不同的供体。
