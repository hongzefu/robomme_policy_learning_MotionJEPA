第一部分（给人看）

1 要做什么

把上一轮跑了约 8.7 小时的同一局 steering 流水线提速到每个模型约 3 小时（目标 2 小时，视冒烟实测），然后用它跑完上一轮没跑的部分：Frozen Wan pooling 的 RouteStick 与 VideoRepick、MotionMem 的 VideoRepick、MotionMem 的 core 窗口组。测的内容与上一轮完全相同（同一局、四种走法、置零、换 seed 噪声）。

上一轮 8.7 小时的去向（审查实测）：变体录制 2.5 h、干预 4.1 h、变体示范生成 1.2 h、不干预 0.5 h、噪声 0.5 h。根因只有一个：motion 窗口被反复在线编码——每段录制、每次干预都把整段示范的全部窗口（xhard 约 30 窗，每窗约 1.7 s，fp32、关 TF32、一次一窗）重编一遍，而真正需要换的只有第 j 段那约 5 个窗。

2 修复项（按收益排序）

#改什么效果口径变化（已获放宽）
F1离线批量编码供体：生成变体示范时只把第 j 段相关窗口的帧存下来，单个 GPU 进程用 bf16、批量把它们一次编完；整个「变体录制」阶段取消变体录制 2.5 h → 约 0.1–0.2 h供体 token 由离线 bf16 批量编码，不再由服务端在线 fp32 编码
F2干预时复用不干预运行录下的示范窗口：非供体的示范窗直接读 N 的录制，只有执行阶段新出现的窗口在线编码干预 4.1 h → 约 1.5–2 h示范窗与 N 同值（跨卡差异不再管）
F3在线编码改 bf16 + TF32（sidecar 的数值钉放开），执行窗口编码随之变快每窗约 1.7 s → 估计 0.3–0.6 s，干预与 N 再快约 1.5–2 倍训练建库口径（policy 仓 docs/dataset-build-doc/4task-v2-1600ep-motion-demopad17/result.md、motion_provenance.json）：Wan VAE fp32、TF32 关、B=1；encoder bf16 autocast；token 存 fp32。所以 encoder bf16 与训练一致，VAE 改 bf16/TF32 是偏离训练的部分（存档实测 BF16 VAE latent RMSE 3.1e-3、最大差 0.029），由 ENC_TOL 把关；Frozen Wan 的池化表全程 fp32
F4共享拉取队列 + 长任务先领：所有通道（GL 与 aspen）从同一个任务池领 spec，按预计耗时从长到短消掉上一轮最多 77 分钟的收工时差无
F5一个 spec 只起一次策略服务约 −5%无

不做：VAE 重叠帧 latent 拼接（因果分组，latent 不等，收益不可靠）；回放示范帧替代仿真（F1 已覆盖其收益）。

3 怎么保证「误差在一定范围内」

闸门查什么判据
ENC_TOL抽 300 个窗口，新编码（bf16、批量、离线）对旧编码（上一轮在线 fp32 录制）每窗余弦 ≥ 0.999，最大绝对差 ≤ 0.1（MotionJEPA 文档实测 bf16 对 fp32：min cos 0.99997、max 0.034）
BEHAVIOR_TOL用新流水线把上一轮 MotionMem「只翻绕向」的 60 个位置重跑一遍跟随率与上一轮差 ≤ 0.05（上一轮 0.89）；不干预成功率同局对比差 ≤ 0.1
NOOP_EQ2用 N 自身录制作供体替换（含 F2 复用），动作与不干预比第 1–3 步判定（按钮、绕向）一致 ≥ 95%（不再要求逐位）

任一闸门不过：记录原值，按第二部分 7 节「闸门 → FAIL 回退」表回退对应修复项，只重测该闸门，不停整条线（ENC_TOL→VAE 回 fp32、保留批量化；NOOP_EQ2→关 F2 复用；BEHAVIOR_TOL→先归因再回退对应项）。
