3.1　9 个 latent 逐个投影：共享一个 Linear

定义：Wan VAE 对一个 33 帧窗输出 raw latent Z，形状 (9,16,32,32) =（时间, 通道, 高, 宽）。latent 0 只编码窗内第 0 帧，latent k（k=1..8）编码窗内偏移 4k−3 … 4k 这 4 帧（Wan 时间压缩 4×，因果首帧单独一格）。窗起点全域帧号为 f。

x_k   = flatten_CHW(Z[k])                       ∈ R^16384,     k = 0..8     （C→H→W：index = 1024c + 32h + w）
τ_k   = f + 4k                                   demo 尾补窗：τ_k = min(f + 4k, 段末真实帧)
p_k   = silu( motion_pos_proj( pos(τ_k) ) )      pos(τ)：帧路 3D posemb 表该帧第 0 行前 256 维 → 768
token_k = W · concat(x_k, p_k) + b               W: 1024 × 17152，b: 1024
  • 锚点：src/mme_vla_suite/models/representation/percep_mem.py 里 motion_encoder_static = nnx.Linear(self.motion_dim + pos_hidden, memory_token_dim) 本来就是「dim + pos_hidden」的式子，yaml 把 motion.dim 改成 16384 即得 17152 → 1024；motion_pos_proj（256→768）原样复用。需要改的是形状检查：现有 motion_emb 断言 (b, motion_budget, motion_dim)，改为 (b, motion_token_budget(mcfg), 16384)（= budget × tokens_per_window）；新 yaml 键 tokens_per_window: 9，缺省 1，旧 yaml 行为逐字不变。共享常量放新模块 src/mme_vla_suite/shared/wan_raw9.py（离线导出、dataset、在线 sidecar 共用，体例同 wan_pool768.py）。
  • 共享：9 个 k、所有窗口、所有样本共用同一个 W（D1）。W 随 VLA 从头训练，属于 mem_encoder 参数；参数量 17152 × 1024 + 1024 ≈ 17.56M。
  • 和 v11 的关系：v11 的「时间均值 + 6×8 平均池化」本身就是一个固定线性映射（权重为 1/8 × 1/24 的常数），后接 Linear(1536→1024)。本轮把固定池化换成可学习 W，并且不再把 8 个时刻平均掉：每个时刻各自 1 个 token，网络自己决定看哪些通道与空间位置。
  • ⚠ latent 0 冗余（D2 接受）：latent 0 只看窗首帧，stride 32 时与上一窗 latent 8（编码上一窗偏移 29–32 帧，即本窗首帧附近）信息重叠；保留是为了「9 个都在」的口径。
  • ⚠ 未归一化：raw latent 不做 z-score、不加 LayerNorm（保持「零额外处理」），沿用旧 kernel_init；尺度是否失衡靠运行中记录项（§5 下方）观察，不预先加保护层。
  • 算力：投影前向全局约 128 × 720 × 17152 × 1024 × 2 ≈ 3.2 TFLOP，反向只需对 W 求梯度（输入是数据），每步约 5–7 TFLOP（量级，毫秒级）；交叉注意 key 从 672 增到 1232，action expert 查询约 50 个，增量可忽略。

3.4　数据管线：瓶颈判定与修复阶梯（用户已授权 L0–L3，含 bf16）

为什么有风险：每步全局 motion 张量约 6.0 GB，是 v11 的 63 MB 的约 100 倍。v11 GPU 均值 97.7%，是计算受限；本轮若 worker 组 batch、跨进程 pickle、主机→GPU 拷贝跟不上，就会拖慢每一步。

五　风险登记

  1. raw latent 未归一化尺度：16384 维 fp32 原值直接进 Linear(17152→1024)，初始 token 尺度可能远大于帧 token，交叉注意被 motion 主导或梯度爆。处置：沿用旧 kernel_init、不预加 LayerNorm/z-score（零额外处理口径），靠 DIAG 的 kernel 梯度范数与每 ckpt 激活均值/方差观察；出现 nan/loss 爆即停报用户。
  2. 17.6M 新参数过拟合：4task × 400 demo 规模下新增约 17.6M 可学参数；只评 50k，无法从本计划区分欠/过拟合，loss 曲线与 25k/50k 激活统计只作旁证。
  3. 双变量混淆（D3）：「不池化」与「stride 32」同时变，结果差异不能归因到其中一个；结论只写「组合方案相对 v11 的差」。
  4. budget 余量：主会话实测 max_visible_s32=71，budget 固定 80（余 9 窗）；导出或校验独立重算若 ≠71，说明 index 口径与实测不一致：>80 停交用户，≤80 按 D8 记录后继续，均不改 budget。评估侧在线可见窗超 budget 时走 resample（按窗），与训练侧口径须一致（S3 单测覆盖）。
  5. page cache 被其他任务挤出：/scratch 多人共用，约 21.5 GB 表依赖页缓存；被挤出后 memmap 退化为随机读 NVMe RAID，dataloader 等待上升。处置：RB-C4 预热、训练中看 dl_wait；持续 30 min > 2 s/步 记录并当轮告知用户（D8），不在训练中途换级；总时长超已批 5 倍才停。
  6. L2 显存不足：表 fp32 约 21.5 GB 驻每卡要求剩余 ≥ 22 GB；v11 配置 XLA_PYTHON_CLIENT_MEM_FRACTION=0.95 下模型峰值未知，需 r9-memprobe 关预分配实测；不足走 L3（分片优先，bf16 次之，用户已批）。
  7. 评估在线 sidecar 每窗 576 KB 传输：raw9 sidecar 返回 (9,16,32,32) fp32，比 pool768 的 3 KB 大约 190 倍；10 片、每卡 ≤2 片并发下 IPC 与序列化可能拖慢单局，EPISODE_WALL_S=2400 有超时风险。处置：闸 G6b（RB-D4）一局加载冒烟记单局耗时并与 v11 比较；VAE 调用数减半部分抵消。
  8. worktree 测试 import 到主检出代码：评估实际加载 src/mme_vla_suite/policies/ 已核实（第二部分 1.2 证据框），但 policy-eval-server venv 的 editable 指向主检出 src，S3 在 worktree 里跑在线测试时容易测到主检出旧代码。处置：S3 验收用 PYTHONPATH=<worktree>/src 并打印 mme_vla_suite.__file__ 确认指向 worktree src；合并后主检出即为新代码，闸 G5 与 闸 G6b 在真实评估环境再验一次。
  9. stride 32 下 exec 段前 32 帧无 motion token：exec 段 u+32 ≤ t−es，执行开始后前 32 帧（stride 16 时为 16 帧）没有 exec motion token，只有 demo 段 token；早期动作只能依赖帧路。已接受（D4），不补救。
  10. 测速代表性：300 步测速在页缓存热、无其他任务时测得，正式 14–15.5 h 中共用盘负载变化可能使实际步速偏离；只按硬停判据处置。
  11. 链脚本误起评估：若链脚本判据写错，可能在 ckpt 不完整时起评估；S4 用 test_raw9_runner_chain.py 三种假日志夹具验收，审查者 RV 必核。

六　盲区诚实清单

  • budget_max 口径：71 与 36,484 行是主会话由 v11 motion_index.json 按 stride 32 合法性规则推算，尚未由导出脚本在真实 latent 上重算；RB-C1/RB-C3 独立重算须一致。

  • memmap 吞吐：16 worker 共享页缓存 memmap 的实际读带宽、每步 6.0 GB 组 batch 与跨进程传输开销未实测，L0 是否够用只能看 RB-D2。

  • 模型峰值显存：budget·9 = 720 个 16384 维 motion 输入在 activations 中的显存占用（每卡 b=16 时约 0.75 GB 输入本身）与交叉注意 key 数 1232 的增量只做了量级估计。
  • raw latent 数值范围：Wan VAE raw latent 的均值/方差未统计（v11 池化后才进网络），初始训练是否稳定只能看起跑前几百步。
  • sidecar 576 KB/窗的单局耗时：在线传输对 EPISODE_WALL_S=2400 的影响未测，闸 G6b 只有 1 局样本。
  • 尾补窗 τ 截断规则：demo 段 repeat_last 尾补窗中重复帧对应的 latent，τ 截到段末真实帧的具体写法（多个 token 同 τ 时 mem_order 的稳定排序）由 S1/S2 落实，训推两侧一致性靠 闸 G4/G5。
  • H5 小样覆盖：闸 G4 抽的 64 窗若落在 $LIB/raw-h5 未下载的 episode，需按 v11 流程补下 tar.xz 对象，下载量未知。
  • 时间估计：14–15.5 h 基于 1.0–1.1 s/步假设（v11 0.966 s/步 + motion 路增量），未测；未修复的最差 17–28 h 同为估算。
