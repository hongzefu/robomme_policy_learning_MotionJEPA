窗口时间与可见性：沿用 motion_store::visible_motion_rows 的因果原则，网格步长改为逐layout读取。exec段内起点u=32m，在当前帧t仅当u+32≤t−exec_start时可见；demo在exec开始后全部可见，含显式起点的保留尾窗；只重复本段末帧，不能将窗口内补帧误作无效槽。两个实验用完全相同的grid32_plus_last16_demo_v1窗口ID集合，先按80窗容量补齐，再分别展开 8/9 槽，mask、窗口起点 PE 和时间键也 repeat8/repeat9。shared/sampling.py::memory_order按“全域时刻、帧先于 motion”的稳定排序一起重排 token 与 mask。

A 的 8 个 query 是学习得到的槽位，不是 8 个时间点。B 的 9 槽是 VAE 的有序时间 latent，各槽有时序感受野，也不是 9 张独立原图。本轮两组都沿用窗口起点时间码，B 槽内次序按 g=0…8 保留；不额外给 B 换成逐槽物理帧时间码。超过80窗就明确失败，不静默裁剪两组的历史。

六、memory modulation 完整展开

Cᵢ = Out(softmax(QᵢKᵀ/√256 + mask)V)
[γᵢ, βᵢ] = Dense(Cᵢ)
uᵢ = RMS(xᵢ) ⊙ (1+γᵢ) + βᵢ
yᵢ = xᵢ + gateffn(τ) ⊙ dropout(FFN(pre_ffw_norm(uᵢ,τ)))

xᵢ是本层 self-attention 残差后的动作状态；最后残差加回它。γ/β 是 memory 产生的 scale/shift，不是原 FFN residual gate。调制 Dense 的 std 为 0.002，与输入适配器的 0.02 区分；现实现是小随机初始化，不能宣称初始状态与无 memory 模型相同。

并行预检与截止协议：把计时、异步存盘和退出路径闭合

预检总上限：两组合并计时最多30分钟，每臂最多120次真实更新，二者先到即以预检不完整结束；该额度包含在原6小时准备预算内，不额外增加预算。它不是正式训练，权重不进入60k run。以下各阶段仍使用完整B128/W80/FSDP4与正式60k学习率日程。

  1. 预热与就绪：每臂完成10次更新并block_until_ready后写READY，包含版本、配置、已完成步数与时间。两组都READY才放行计时；READY/首次有效更新的等待从各进程启动起最多20分钟，且受预检30分钟总截止限制。就绪前一臂失败或到期，取消另一臂等待并仅清理本次进程，不能卡住空等。
  2. 20次共驻计时：同一START信号后，两臂各自计20次真实更新，起止均同步完成态。先计完者继续非计时更新作为陪跑，直到另一臂完成计时；记录陪跑步数，不能让它退出后把慢臂尾段称为并行性能。超过120次或时间上限则不放行。每臂报告20/T_i的完成吞吐及两臂区间，不能由host_step_s反推任意子区间的GPU完成步数。
  3. 共同触发非终点保存：双方计时完成后在下一个更新边界汇合，记录各自真实step，然后同时调用原save_state异步保存。保存返回后，每臂继续至少5次真实更新和取批，再等待后台保存完成；采集覆盖保存请求、后台完成、后续计算/H2D的全部主机/SHM/GPU峰值。记录保存状态与观察到的重叠，不用纯终点保存替代。此诊断保存只在smoke控制路径触发，正式save_interval仍5000。
  4. 读回与封口：等待全部保存结束，严格回读该中途checkpoint并与保存时的序列化EMA参考对比；不是拿后续更新后的EMA作参考。报告两臂实际更新总数、计时步与陪跑步、保存/等待耗时及所有退出码。失败不改判据、不自动重试；未覆盖中途保存继续更新路径时，CAPACITY_AB不得通过。

正式截止：双臂控制器记录准备T0与训练阶段T1，固定 D=min(T0+46小时,T1+40小时)，把同一个绝对截止传给两臂（专用配置新增deadline_unix_s/save_reserve_s，旧入口缺省关闭）。到D−15分钟或收到停止请求时，训练器在更新边界停止提交新更新，保存实际已完成步数的权重并等待完成；signal handler只置停止标志，不能在信号回调中直接保存。部分完成必须 complete=false，不能伪装60k。

训练器的正常/异常收尾都把checkpoint等待放入finally并记录失败；外部控制器不受内部阻塞影响。到D−60秒仍未退出时，向已登记且归属核验通过的本次进程组发TERM；D时仍存活则KILL并记超时及保存是否完成，不能因Orbax内部7200秒超时默认值延长预算。两臂各自保留原始退出码和停止原因；训练已开始后一臂失败，另一臂按既定合同继续至自身60k或共同D。所有cleanup只针对本次PID/进程组/tmux，不做全局pkill。
