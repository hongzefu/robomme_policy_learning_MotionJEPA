第一部分（给人看）

一、要做什么

回应审稿意见「干预只在简化的单子目标局上，与正式多步任务之间还差一步」：在多步局的每个长度、每个子目标位置 j 上，只替换覆盖第 j 个子目标的示范 motion 窗口，读第 j 步是否跟供体走，同时读其他各步是否不受影响，做成「干预位置 j × 被影响子目标 i」矩阵，看有没有对角结构。三个交换任务的「位置」是第 k 次交换，读数仍是第一次拿起。

任务长度（子目标数 m 或交换次数 n）位置数读什么
PatternLockeasy m=1–3、medium 2–4、hard 3–7（m = 节点数 − 1）m=1..7 共 28 个 (m,j)每一步到达哪个格

三、机制

子目标在示范里的帧段：示范只保留 move 段（DemonstrationWrapper._filter_no_record_from_step_batch）。RouteStick 每步固定 50 帧（solve_swingonto_withDirection 45 步 + 5 保持），第 j 步是帧 [50(j−1), 50j)。PatternLock 每步帧数随规划长度变化（单步 17–48 帧），所以由新扫描在 reset 时记录每个示范帧所属的子目标，得到第 j 步的帧段 [a_j, b_j)。

第 j 个子目标的窗口集合 W_j：示范窗起点 s=0,32,…（s+16 ≤ es−1，尾窗补帧），真实帧范围与 [a_j, b_j) 相交即入 W_j。跨两个子目标的窗口记为「跨界」，同时属于两个 W；矩阵按「跨界窗是否算入」报两版（全部 / 只换完全落在第 j 段里的窗）。交换任务第 k 次交换同理用交换帧区间 [start_k+1, end_k+1]。

替换：沿用 motion_swap_exact + 合成供体键（FP 计划〇′ F2），供体按「W_j 内顺序」对齐，服务端不改。

⚠ 第 j 段的 token 在开局就全部可见，所以它也可能影响 j 之前的步——这正是特异性矩阵要测的；j 之后的步一旦第 j 步被带偏，起点就变了，只在第 j 步走回自己目标的局上解读。

四、分组（每个接收局、每个位置 j）

组W_j 换成什么说明
N 原样不换每局一次；给出「碰巧到达供体目标」基线与筛选条件
Bsame另一局同位置 j、子目标不同的窗口PatternLock：方向不同且从接收局第 j 步起点走供体方向仍在盘内；RouteStick：左右或绕向不同且可执行；交换任务：另一局第 k 次交换窗口
Bcross另一局不同位置 j′≠j、子目标不同的窗口（条件同上）测 token 是否与时序位置绑定；交换任务不做（交换位置语义不同）
Z零向量去掉第 j 段 motion
F（反向对照，优先级 3）第 j 段帧 token 换成同一供体的帧，motion 保留原样需要新写服务端替换示范帧的路径；赶不及就不做并在结果中写明

只在 N 运行里走到第 j 步起点的 (局, j) 上做干预（第 j 步之前的步在 N 里都完成；不要求整局成功）。走不到的位置读不出第 j 步，干预它没有信息量。

五、读数与矩阵

  • 每次运行逐步复原：第 i 步到达的格（step_trace 的 task_index 跳变时 tcp 最近格）与 RouteStick 绕向。
  • 第 j 步：own / donor_dir（从接收局实际起点走供体方向）/ donor_abs / other / none；RouteStick 另 own_swing / donor_swing。
  • 矩阵 M[j][i]：i<j 为「与 N 同一结果」的保持率；i=j 为跟随供体率；i>j 为第 j 步 own 的局上后续步正确率。PatternLock、RouteStick 各按 m 分块，再合并按 j 汇总。
  • 主分析（不筛选）：全部干预局的跟随率 − N 中到达同一供体目标的比率；补充：只看 N 中第 j 步本身正确的局。
  • 统计：每个 (m,j) 报 n；置信区间按接收局重采样 2000 次。
