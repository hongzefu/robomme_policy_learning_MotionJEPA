第一部分（给人看）

一、要做什么

让基线和 motion 两个模型各自完整跑 StopCube 官方 50 局，全程由模型控制，不用 Oracle 悬停、不接管、不跳步。跑的时候只记录真实发生的轨迹和每次推理的完整输入；注意力和隐状态事后对这些输入离线计算，这样分析不会影响实际执行的动作。用这一批数据回答四个问题：

编号问题用什么回答
Q1触发时刻的分布是否在窗口内逐步轨迹的按钮字段 + 窗口表
Q2按的那一刻有没有看 motion下压前后几次推理的注意力，用模型实际执行的噪声算
Q3模型知不知道离自己按还有几步线性探针，标签来自它自己的真实触发时刻
Q4模型知不知道离正确窗口还有几步线性探针，标签来自窗口表

三、机制

1. 为什么不能直接用现有的 rollout 数据

中止计划留下了 motion 模型 28 局完整 rollout 和 1 局中断（第 28 局），共 29 条轨迹（v1-store/evaluation/stopcube-decision-1104/normal/，436 次推理，38 G）。它不能当本轮结果，原因有三个：没有基线；infer_*.npz 里没有图像和记忆输入，算不了隐状态；AttnRecorder 把 policy._sample_actions 换成了展开路径，实际执行的动作走的不是原路径。上一轮测到展开路径的归一化动作最大差：基线 0.0437、motion 0.0166（OFFLINE_REPLAY 判定行）。所以本轮新增一个只记录、不换路径的记录器。

2. 中止数据已经验证的事实（motion 模型，28 局完整、第 28 局中断）

3. Q1：触发时刻分布

定义和上一轮一致（oracle_press_prob.py 的分类）：trigger_step 是 button_pressed_after 首次为真的 env_step_after；窗口是窗口表的 target_visit_in～target_visit_out。每局分成未按、偏早、窗口内、偏晚四类，并计算 trigger_step − 窗口中心。

产出：两个模型的四类计数表；按 M＝60/80/120 分层；相对窗口中心的分布图；逐局配对表；局级重采样的差值区间。官方 task_success 单独报告，因为几何窗口和官方判定不完全一致：上一轮第 9 局就是在窗口内却判失败。

4. Q2：按的那一刻有没有看 motion

注意力用这次推理实际执行的那份噪声计算，因为它才是真正导致这次动作的那一次采样。统计沿用 offline_mechanism.aggregate_attention：前 16 个动作位、10 个去噪步取平均，保留 18 层×8 头。

对齐点定义适用的局
I_cross动作块内首次出现实测 TCP 低于悬停 2 cm 的那次推理有下压的局
I_cross−1、−2、−3下压之前的推理，作同局对照；I_cross−1 通常已经发出下压指令同上，不足的如实缺失
I_trigger动作块内发生按钮触发的那次推理已触发的局
I_near动作块覆盖窗口中心的那次推理，单独成组未按的局

回答「有没有看 motion」要比较三样东西，只看总占比是不够的：

  • 和自己之前比：同一局 I_cross 对比 I_cross−3 的 motion 单 token 占比。因为 motion token 数会随时间增加，所以用单 token 占比，并同时列出 token 数。
  • 和均匀分配比：motion 实际占比对比「motion token 数 ÷ 有效 token 数」。
  • 和其他输入比：同一次推理里当前画面、历史帧、文字、动作 token 的占比。基线没有 motion，只比其余几组。

另外三项：

  • 头：144 个头全部统计。L13H6、L15H1、L16H0 在开跑前就定为候选，用来检验上一轮 8 个点上的现象能否在全部 50 局上重现；其余的头只作描述。
  • 看的是哪段 motion：新记录 motion_times，把被关注的窗口分成「覆盖方块此前经过目标的时段」和其他，并与均匀分配比较。
  • 分组：全部结果按窗口内、偏早、偏晚分组，不按成功挑局，消除上一轮的选择偏差。

辅助量：每次推理用 10 份独立噪声走原路径算一次想按比例 P（定义同 oracle_press_prob.probabilities），用于看实际轨迹上的想按曲线。这些预测不执行。到位之前（TCP 尚未到悬停高度）的点不计 P。

5. Q3、Q4：线性探针

隐状态由离线展开路径按实际噪声取得，按组取均值后保存：前缀隐状态分帧、motion、当前画面、文字四组，共 19 个读数（第 0 层输入加 18 层输出）；动作 token 取前 16 个、10 个去噪步的平均，18 层。

标签样本范围
Q3 离自己按trigger_step − 推理起点步只用已触发的局；到位后到触发前的推理
Q4 离正确窗口窗口中心 − 推理起点步，可为负；窗口中心等于 M×(N−0.5)全部进入 Q4 的局（正常为 50 局）；到位后到本局结束的推理

⚠ 关键陷阱：标签几乎就是时间的线性函数。Q4 的标签等于 M(N−0.5) − t。模型的记忆里带时间码（所以可能知道 t），指令里写着次数（所以知道 N）。只要探针读出 t 和 N，就能得到很高的 R²，但这不代表模型有「预期」。真正需要模型算的是方块周期 M。所以判断标准不是 R² 高不高，而是能不能超过下面的对照：

对照做法防的是什么
时间基线（主比较）只用 t 和 N 做同样的回归探针只是读出了时间和指令；探针必须比它的误差更小，才算有额外信息
第 0 层输入前缀探针用同组 token 进入第 0 层之前的表示；主读数用前缀四组第 0 层均值拼接（K9）信息在输入里就有，并不是模型算出来的
只用当前画面只用当前画面组的隐状态只靠当前画面就能猜
按局打乱标签整局一起打乱后重做过拟合；样本数远小于特征维度时尤其需要

方法：闭式岭回归（只用 numpy，不新增依赖）；两个模型用相同的 5 折按局划分，同一局不跨折；正则系数在训练折内部选择；标准化只用训练折。输出折外 MAE（单位：步）和 R²，每局等权，避免长局主导；用局级重采样给出「探针 MAE − 时间基线 MAE」的区间。主要读数预先定为第 17 层动作 token；其余层和组只作描述，画成逐层曲线。

可能的结果能说什么不能说什么
探针不优于时间基线这批样本里，没看到超过时间和次数的信息不能说模型没有预期：线性探针和约 780 个样本都有局限
探针优于时间基线，且优于第 0 层隐状态里有模型计算得到的进度信息，可解码不能说模型用了这个信息
第 0 层已经一样好信息在输入里就有不能归功于模型内部计算
motion 模型优于基线只描述差异两个模型训练来源不同，不能全部归因于 motion

⚠ Q3、Q4 的样本结构不同：Q3 不含未按的局；偏早的局没有窗口附近的样本，偏晚的局有。两个模型触发分布不同，样本也就不同，所以另外在「两个模型都有样本的局」上重算一遍。

六、盲区诚实清单

  • 只有一个模型 seed、一次运行、50 个固定局；统计单位是局，不是推理。
  • 两个模型训练来源和步数不同，差异不能全部归因于 motion。
  • 每 16 步一次推理，决策的准确时点可能夹在两次推理之间。
  • 注意力只看动作 token 的直接读取，不覆盖跨层间接路径。
  • 线性探针读不出非线性编码的信息；可解码也不等于模型使用了它。
  • 展开路径与原路径有微小数值差异，注意力和隐状态是在展开路径上取的，差异如实记录。
  • 第 0 层对照按组取平均，会丢失单 token 细节，所以这个输入对照可能偏弱；它的拼接维度也和第 17 层动作 token 不同，motion 模型四组、基线三组，比较时会混入特征维度和岭回归容量的影响，跨模型只作描述。
  • 模型实际运行在 bfloat16 精度，开关隐状态捕获有数值波动（第十节），注意力和隐状态都取自开启捕获的那次运行。motion 模型后段的历史帧组和当前画面组，精度误差对点间距离的余量只有约 8 倍（未达 10 倍），这两组的逐层曲线和第 0 层对照要谨慎读；主读数约 200 倍、motion 组约 120 倍。
  • 没有干预，所以 Q2～Q4 都不能回答「靠什么决定」。
