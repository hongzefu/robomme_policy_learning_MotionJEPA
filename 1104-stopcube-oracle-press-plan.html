第一部分（给人看）

要做什么

让 Oracle 规划器把机械臂送到按钮上方并一直保持，模型照常看真实画面、照常推理，但它的动作不执行。这样每局都能看到模型在每个时刻「想不想按」，然后选一个区间之前的时刻把控制权交回模型，看它是否真的按下、按得准不准。

用户原话：「通过 simulator 本身直接计算出它这个真正的下压位置区间，然后……用 Oracle 的 Planning 的 model 直接去到达这个位置，然后再来……进行模型的推理，就是在这个位置前后去做进行模型的推理，然后去判断这个模型真正按下去的这个可能的比例有多少。」

和旧计划的差别：旧计划只给提前按错的 E 局补一条悬停轨迹，历史来自模型自己。新版 50 局全部由 Oracle 到位，不再有 E，也不再依赖模型自己走到悬停位置。

为什么推理范围不能只取「区间前后」

按 50 局的真实 seed 推算（M、N 取自 StopCube._initialize_episode 的同一随机序列，推理边界固定为第 1+16k 步）：

事实数字影响
可停区间宽度M=60／80／120 约 9／11／17 步（第 16 局实测 412～428）区间普遍比 16 步的推理间隔窄
区间内的推理次数30 局为 0 次，20 局为 1 次；M=80 的 22 局全为 0 次只在区间内推理，六成的局一个样本都没有
第 16 局实际下压（成功局）第 385 次边界的动作块里 TCP 约在第 397 步开始下降；目标高度第 403 步过阈值；第 416 步触发决定下压的推理（385、401）都在区间之外，一次下压还跨了两个动作块

所以新版测的是整段悬停期的全部边界，共约 943 次推理（50 局 M·N 合计 14,920 步）。这样还能回答一个更重要的问题：模型是在正确的第 N 次经过才想按，还是每次方块经过都想按。一个总想按的模型，只看区间内的比例也会很高。

机制

Oracle 动作表。在同 seed 环境里实例化 FailAwarePandaArmMotionPlanningSolver，调用任务自带的 task_list[0]["solve"]（即 solve_button_ready），之后反复 planner.close_gripper() 保持（与 solve_hold_obj_absTimestep 相同）。规划器通过 env.step 推进环境，所以在 step 入口记录 8 维动作即可得到逐步表。另跑一个带下压的版本，到 T-30 调 solve_button，用来验证区间和测量 Oracle 自身的耗时。

为什么 Oracle 历史是合理输入。任务定义的示范流程正是「到悬停位、保持、下压」，输入分布比模型自己走到悬停位更接近其任务定义。代价是结果只代表理想历史下的能力，不能解释真实失败（见盲区）。

下压判据。对每个样本的 20 行动作逐行换算目标 TCP 高度。阈值 z_thr = z_hover - 0.02，z_hover 取本局 Oracle 悬停段的实测高度，因为定义值 0.15 m 与第 16 局模型实际悬停高度约 0.160 m 差了 1 cm，相对 2 cm 阈值不能忽略。同时报 0.01／0.02／0.03 三档的敏感性。

onset_exec(s, b)    = 前 16 行（实际会执行）里首个 z < z_thr 的行；无则为空
onset_horizon(s, b) = 全部 20 行里的同一量（反映意图，第 16 局的 385 这次属于这种情况）
P_exec(b)           = 32 个样本中 onset_exec 非空的比例
pred_trigger(s, b)  = b + onset_exec + d        # d 为命令到触发的实测耗时
在区间内            = pred_trigger ∈ [target_visit_in, target_visit_out]

怎么读结果。主图横轴是「边界距 T 的步数」，纵轴是 P_exec，按 M 分面，并按第几次经过分组，再标出在区间内的比例。

现象含义
只在第 N 次经过之前陡升能区分次数和时机
每次经过都升高能感知方块位置，但没数对次数
第 N 次也不升高，或全程平坦这段历史下基本不想按，或与方块经过无关
上升时刻系统性偏早或偏晚时序偏差，配合闭环的触发步核实

两层结果互相校验。由开环比例按 S(b)=∏(1-P_exec) 累乘可估出「首次下压落在区间内」的比例，再与放手后的真实比例对比。这个估计假设各次推理独立且下压不会中途放弃，两者差异如实报告，不用来修正任何一方。

4.3 放手点

B = {1 + 16k}，T = M(N - 1/2)
候选 = {b ∈ B | reach_step ≤ b ≤ T - 48}
候选非空: release_step = max(候选), release_kind = before_t48
候选为空: release_step = min{b ∈ B | b ≥ reach_step}，且须 b < target_visit_in，release_kind = late_release
仍不存在: release_kind = none，该局不跑闭环，列入报告

第 16 局 T-48=372，放手点为 369，模型之后还有 369、385、401 三次边界可在区间前决定下压。M=60、N=2 的 6 局 T-48=42，很可能落入 late_release，报告分组呈现。

4.4 采样噪声

噪声由固定种子、局身份、轨迹类型、推理序号、样本序号派生的独立 key 生成，不从策略 RNG 取。采样放在 _orig_infer 返回之后，保证真实推理时序不变。batch 大小默认 32，显存不足时分批，只改分批数，不减样本数。

五 分析定义

  • 高度：TcpReader.set_arm 逐行换算，(32,20)。手指关节沿用 reset 值。不跑物理步，只表示目标姿态的高度，不是实测 TCP。
  • 耗时 d：对每个放手局和正常局，用同一 z_thr 取已执行命令首次过阈值的步到按钮触发的步，按 M 报告分布，pred_trigger 取中位数。Oracle 的耗时单独报告，不混入。没有足够下压局时标明，pred_trigger 相关结果写「不可得」。
  • 经过分组：按 visits 把边界划到第 1…N 次经过，以及经过之间。每组报告 P_exec 均值和局级 bootstrap 区间。
  • 闭环分类：按真实触发步分「早于区间／区间内／晚于区间／没按」，任务成功字段独立报告。
  • 对照：同局比较放手结果与正常结果。两者历史和随机数都不同，只比较分布，不解读单局差异。

十 盲区诚实清单

  • 开环比例表示「预测动作满足下压判据」，不等于按钮触发或任务成功；一次下压跨两个动作块，P_exec 只反映起始。
  • Oracle 历史是理想条件。如果真实失败来自模型自身轨迹的累积偏差，开环结果看不出来。
  • 放手点只有一个，结果依赖选点规则；late_release 的局不能与其他局直接合并。
  • 只有一个模型 seed、50 局，部分 (M,N) 格子只有 2 局，结论不能外推。
  • 累乘估计假设相邻推理独立，这在记忆模型上不成立，只作粗略对照。
  • 目标高度来自关节目标的运动学换算，真实 TCP 有滞后。
  • 本计划不回答「模型依据什么决定下压」。
