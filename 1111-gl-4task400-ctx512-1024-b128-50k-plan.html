2. 关键机制

2.1 梯度累积（新写代码，训练链路改动）

为什么非改不可：训练代码没有累积开关（grep -iE "accum|microbatch" 对 scripts/training/train.py、src/mme_vla_suite/training/*.py 零命中）。A100 4 卡 context 512 b128（每卡 32）实测峰值 73,005～73,019 MiB/卡（docs/training-doc/ctx-stock-scaling-20260928/result.md），A40 只有 48 GB；GL 4×A40 每卡 16 的 context（1101，带 motion）峰值 38,489 MiB。

锚点：scripts/training/train.py::train_step；src/mme_vla_suite/training/config.py::TrainConfig 新增 grad_accum_steps: int = 1（CLI --grad-accum-steps）。

B = batch_size; K = grad_accum_steps; m = B // K
micro = tree_map(lambda x: x.reshape(m, K, *x.shape[1:]).swapaxes(0, 1), batch)   # 第 i 个 micro = 样本 i::K
def body(acc, (i, mb)):
    l, g = value_and_grad(loss_fn)(model, fold_in(train_rng, i), *mb)
    return (acc[0] + l / K, tree_map(lambda a, b: a + b / K, acc[1], g)), None
(loss, grads), _ = lax.scan(body, (0., zeros_like(grads)), (arange(K), micro))
updates = tx.update(grads, ...)          # 每个优化步只更新一次
# K == 1 时走原代码路径，一字不改

⚠ 不能直接 reshape(K, m)：batch 在 FSDP 数据轴上按 dim0 连续切给 4 卡，那样第 0 个 micro 只落在前 2 卡。必须 reshape(m, K).swapaxes(0,1)，每 micro 每卡 m/4 个样本。

⚠ flow-matching 噪声按 rng 与 batch 形状采样，K=2 与 K=1 噪声不同，做不到逐位一致；按第 18 条分层验收（§3 V1–V4）。

2.6 完整状态续跑（用户批准新增）

为什么：现有 ckpt 只存 EMA 权重（src/openpi/training/checkpoints.py::save_state 里 "train_state" 一项被注释掉），train.py::main 开头因此禁用 --resume（原话「续跑语义有损（checkpoint 只存 EMA，丢 AdamW 动量与 warmup 计数）」）。

改法：① 每次保存时另存一份完整训练状态（raw params、AdamW opt_state、step、EMA、rng）到 <run>/resume/，只保留最新 1 份（估计数十 GB，不随 10 份 EMA ckpt 累积）；② 数据顺序（r3，用户选「续跑只要求不重复样本」）：全新 run 的样本序列不动（仍是原 TorchDataLoader 的 RandomSampler，V1 逐位成立）；续跑时由 train.py 把 dataloader 的 seed 换成 seed + 1000003 × start_step 重新打乱，不要求与不中断时同序，不改 src/openpi/training/data_loader.py；③ 新开关 --resume-full：只有 resume/ 完整（含 manifest 与 sha）才放行，否则 fail-loud；它在内部以 resume=True 调 checkpoints.py::initialize_checkpoint_dir（放行已存在的 run 目录），但只从 resume/ 恢复完整状态，不走已是死代码的 restore_state；旧的 --resume / --overwrite 照旧报错；④ 入口脚本加 RESUME=1，此时允许 run 目录已存在，否则仍拒绝。

⚠ V10（r3）：续跑后数据重新打乱，所以不比 loss 序列，改为逐位核状态：小子集 40 个样本、global 4、K=2（每 epoch 10 步），跑 15 步保存 → 新进程 --resume-full 读回，读回的 params / opt_state / ema / step / rng 与保存前逐位相同；再续跑 15 步（跨两次 epoch 边界）全程 finite、正常退出。

续跑操作流程：EMA ckpt 与 resume/ 在同一 step 保存；主会话等到选定 step 的 resume/manifest.json 落盘后主动 kill-session 停止旧占位里的训练（不等 walltime 杀），再在新占位以 RESUME=1 起跑。原子改名期间 turbo 峰值为 2 份 resume/。

七 盲区诚实清单

  • A40 上 context b128 累积 2 的步时与显存从未实测；ctx1024 步时连 A100 都只是内插。
  • bucket 训练子集的精确字节数未列（本机 hf buckets list -R 未返回内容），由 CPU job 的 dry-run 给出。
  • 完整 train_state 单份体积未测（raw params + AdamW 两份矩估约为参数量 × 12～16 字节）。
  • 续跑后的样本顺序与不中断时不同（用户口径「只要求不重复样本」），续跑前后两段的样本分布只在统计上等价。
  • modulation 对照 1024 @50k 是否取自 80k run 的第 50000 步，以 V11.89 记录为准，未再核 ckpt。
